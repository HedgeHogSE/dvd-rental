# Техническое задание
## Система видеопроката DVD-дисков

### 1. Общая информация

Учебный веб-проект для управления видеопрокатом DVD-дисков.

**Стек:**

- Backend: PHP + Laravel
- Frontend: React
- База данных: PostgreSQL
- API: REST
- Аутентификация: Laravel Sanctum

Проект должен быть достаточно простым для учебной работы. Основная задача — реализовать CRUD, роли, бронирование и систему блокировок.

---

# 2. Пользователи и роли

В системе должны быть следующие роли:

### Клиент

Может:

- просматривать каталог;
- просматривать информацию о фильмах;
- создавать бронирования;
- просматривать свои бронирования;
- отменять свои бронирования.

### Сотрудник

Может:

- выполнять все действия клиента;
- добавлять, изменять и удалять фильмы;
- управлять DVD-дисками;
- просматривать все бронирования;
- оформлять выдачу и возврат дисков.

### Администратор

Может:

- выполнять все действия сотрудника;
- управлять пользователями;
- назначать пользователям роли;
- блокировать и разблокировать пользователей.

**Важно:** один пользователь может иметь несколько ролей одновременно.

---

# 3. Основные сущности

Для проекта достаточно следующих сущностей:

1. User — пользователь.
2. Role — роль.
3. Movie — фильм.
4. Genre — жанр.
5. Dvd — физический DVD-диск.

- `duration`

- `id`
- `name`

Примеры:

- Комедия
- Драма
- Боевик
- Ужасы
- Фантастика

Необходимо реализовать полный CRUD.

# 8. DVD-диск

Фильм и физический диск — разные сущности.

Например:

```text
Фильм: Матрица

DVD №1
DVD №2
DVD №3
```

## Dvd

Поля:

- `id`
- `movie_id`
- `inventory_number`
- `status`
- `price_per_day`

### Статусы

- `available` — свободен;
- `booked` — забронирован;
- `rented` — выдан;
- `unavailable` — недоступен.

Инвентарный номер должен быть уникальным.

Необходимо реализовать CRUD для DVD.

---

# 9. Бронирование

Это основная функция системы.

## Booking

Поля:

- `id`
- `user_id`
- `dvd_id`
- `start_date`
- `end_date`
- `status`
- `created_at`

### Статусы

- `active`
- `cancelled`
- `completed`

Клиент выбирает DVD и период бронирования.

Пример:

```text
DVD №15
Начало: 10.10.2026
Конец: 13.10.2026
```

После создания бронирования DVD становится недоступным для другого бронирования на пересекающийся период.

---

# 10. Проверка бронирования

Перед созданием бронирования система должна проверить:

1. Существует ли DVD.
2. Не находится ли DVD в статусе `unavailable`.
3. Не забронирован ли DVD на выбранный период.
4. Не арендован ли DVD в этот период.
5. Не заблокирован ли пользователь.

Если условия нарушены, бронирование не создаётся.

---

# 11. Система блокировок

Необходимо реализовать блокировку пользователя.

## Block

Поля:

- `id`
- `user_id`
- `reason`
- `created_at`
- `expires_at`

Администратор может заблокировать пользователя.

Заблокированный пользователь не может создавать новые бронирования.

После окончания срока блокировки пользователь снова может пользоваться системой.

Если `expires_at` отсутствует, блокировка считается постоянной.

---

# 12. Блокировка при бронировании

Необходимо предусмотреть защиту от ситуации, когда два пользователя одновременно пытаются забронировать один DVD.

Например:

```text
Пользователь A ──┐
                 ├── DVD №10
Пользователь B ──┘
```

Если оба отправили запрос практически одновременно, система должна гарантировать, что одно и то же время не будет забронировано дважды.

Для этого при создании бронирования необходимо использовать транзакцию базы данных и блокировку записи.

В Laravel можно использовать:

```php
DB::transaction(...)
```

и:

```php
lockForUpdate()
```

Не требуется реализовывать сложную распределённую систему блокировок.

---

# 13. Аренда

После бронирования сотрудник может выдать DVD клиенту.

## Rental

Поля:

- `id`
- `user_id`
- `dvd_id`
- `booking_id`
- `issued_at`
- `returned_at`
- `status`
- `price`

### Статусы

- `active`
- `returned`

При выдаче:

```text
DVD → rented
Rental → active
```

При возврате:

```text
DVD → available
Rental → returned
```

---

# 14. Стоимость аренды

Стоимость рассчитывается на основании:

```text
количество дней × цена DVD за день
```

Например:

```text
Цена: 100 ₽/день
Срок: 3 дня

Стоимость = 300 ₽
```

Сложную систему тарифов реализовывать не требуется.

---

# 15. CRUD

CRUD должен быть реализован для основных сущностей:

| Сущность | Create | Read | Update | Delete |
|---|---:|---:|---:|---:|
| Пользователь | Да | Да | Да | Да |
| Роль | Да | Да | Да | Да |
| Фильм | Да | Да | Да | Да |
| Жанр | Да | Да | Да | Да |
| DVD | Да | Да | Да | Да |
| Бронирование | Да | Да | Да | Да |
| Аренда | Да | Да | Да | Да |

При этом доступ к операциям ограничивается ролями.

Например, клиент не должен иметь возможность удалить фильм.

# 19. Валидация

Backend должен проверять входные данные.

Например:

- email должен быть корректным;
- email пользователя должен быть уникальным;
- обязательные поля не должны быть пустыми;
- год выпуска должен быть корректным;
- цена аренды должна быть больше или равна нулю;
- дата окончания бронирования должна быть позже даты начала;
- инвентарный номер DVD должен быть уникальным.

# 20. Тестирование

Достаточно написать тесты для основной логики.

Минимальный набор:

1. Пользователь может зарегистрироваться.
2. Пользователь может авторизоваться.
3. Клиент может создать бронирование.
4. Нельзя забронировать уже занятый DVD.
5. Заблокированный пользователь не может создать бронирование.
6. Сотрудник может оформить выдачу DVD.
7. Сотрудник может оформить возврат DVD.
8. Пользователь без нужной роли не может выполнить административную операцию.

Отдельно желательно проверить конкурентное бронирование одного DVD.
